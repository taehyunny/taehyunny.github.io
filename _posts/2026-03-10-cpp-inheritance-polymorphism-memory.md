## 상황

C++에서 상속과 다형성을 공부하면서 단순히 문법만 외우는 것보다, 실제 객체 메모리 안에서 어떤 일이 일어나는지 이해하고 싶었다.

특히 일반 상속과 `virtual` 함수가 들어간 상속은 겉으로 보기에는 비슷해 보여도, 메모리 구조와 함수 호출 방식이 다르다. 그래서 이번에는 정적 바인딩, 동적 바인딩, `vptr`, `vtable`, 중첩 클래스의 차이를 정리해봤다.

## 일반 상속과 가상 함수의 차이

일반적인 상속은 단순히 데이터의 확장에 가깝다.

부모 클래스의 멤버 변수 위에 자식 클래스의 멤버 변수가 이어 붙는 구조이고, 함수 호출 대상은 컴파일 시점에 결정된다.

반면 `virtual` 함수가 들어가면 객체 안에 숨겨진 포인터가 추가된다. 이 포인터가 `vptr`이고, 실제 호출할 함수 주소 목록인 `vtable`을 가리킨다.

즉 일반 상속이 “데이터의 확장”이라면, 가상 함수를 포함한 상속은 “함수 주소록을 통한 실행 시점 선택”이라고 볼 수 있다.

## 정적 바인딩

정적 바인딩에서는 포인터 타입을 기준으로 호출 함수가 결정된다.

```cpp
class Parent {
    int a;
    void show();
};

class Child : public Parent {
    int b;
    void show();
};
```

메모리 배치는 단순하게 생각하면 다음과 같다.

```text
[ int a (4B) ] + [ int b (4B) ] = 총 8바이트
```

패딩은 제외한 단순화된 예시다. 이 구조에서는 추가적인 가상 함수 포인터가 없기 때문에 멤버 변수 크기의 합에 가깝게 객체 크기가 결정된다.

## 동적 바인딩

동적 바인딩은 `virtual` 함수가 있을 때 발생한다.

```cpp
class Parent {
    int a;
    virtual void show();
};

class Child : public Parent {
    int b;
    void show() override;
};
```

64비트 환경에서는 보통 객체 안에 `vptr`이라는 8바이트 포인터가 추가된다.

```text
[ vptr (8B) ] + [ int a (4B) ] + [ int b (4B) ] + [ padding ]
```

이때 `vptr`은 클래스마다 만들어지는 `vtable`을 가리킨다. `vtable`은 실제 실행할 함수 주소 목록이다.

그래서 부모 포인터로 자식 객체를 가리키더라도, 실행 시점에 `vptr -> vtable -> 실제 함수 주소`를 따라가 자식의 재정의된 함수를 호출할 수 있다.

이 구조 덕분에 다형성을 사용할 수 있지만, 객체 크기가 포인터 크기만큼 늘고 함수 호출 시 한 번 더 주소를 따라가는 간접 참조가 생긴다.

## 상속과 중첩 클래스의 차이

상속과 중첩 클래스는 코드상으로 모두 클래스 안에 다른 클래스 이름이 등장할 수 있지만, 관계는 완전히 다르다.

상속은 `Is-A` 관계다.

> 나는 부모의 진화형이다.

자식 객체를 만들면 부모의 데이터와 자식의 데이터가 하나의 객체 메모리 블록 안에 함께 들어간다. 부모 설계가 바뀌면 자식도 영향을 받기 쉽다.

반면 중첩 클래스는 범위를 제한하는 도구에 가깝다.

> 나는 이 클래스 안에서만 쓰이는 도구다.

중첩 클래스를 정의했다고 해서 외부 클래스 객체의 크기가 바로 커지지는 않는다. 실제로 중첩 클래스의 인스턴스를 멤버로 만들 때에만 메모리를 차지한다.

## 상속 예시

```cpp
class DSButton : public QPushButton {
    int buttonID;
};
```

`DSButton` 객체를 만들면 그 안에는 `QPushButton`의 데이터와 `buttonID`가 함께 들어간다. 일체형 구조라고 볼 수 있다.

## 중첩 클래스와 합성 예시

```cpp
class DSOrderManager {
public:
    class OrderItem {
        int id;
        int price;
    };

    OrderItem currentItem;
};
```

`OrderItem`은 `DSOrderManager` 안에 정의되어 있지만, `DSOrderManager` 그 자체는 아니다. 외부 클래스가 내부 클래스를 멤버로 가질 때 비로소 해당 공간이 객체 안에 생긴다.

## 장바구니 객체에서의 고민

장바구니 내부에서만 쓰이는 주문 임시 객체라면 중첩 클래스로 캡슐화할 수 있다.

```cpp
class DSCart {
private:
    class OrderDraft {
        double price;
        int productId;
        int quantity;
        bool isTaxFree;
    };
};
```

여기서 `double`처럼 큰 타입을 먼저 배치하고, `int`, `bool`처럼 작은 타입을 뒤로 배치하면 패딩으로 생기는 메모리 구멍을 줄이는 데 도움이 될 수 있다.

만약 `OrderDraft` 안에 `virtual` 함수를 넣으면 모든 상품 객체마다 `vptr`이 추가된다. 상품 객체가 수백 개라면 8바이트 차이도 무시하기 어려워질 수 있다.

그래서 장바구니 내부의 상품들이 서로 다른 동작을 할 필요가 없다면, 굳이 `virtual`을 넣지 않는 편이 더 단순하고 가벼운 설계일 수 있다.

## 다형성을 다루는 키워드

### `virtual`

부모 클래스에서 “이 함수는 자식이 재정의할 수 있다”고 여는 키워드다.

실행 시점에 실제 객체 타입을 기준으로 함수를 호출할 수 있게 만든다.

### `override`

자식 클래스에서 부모의 가상 함수를 재정의한다는 의도를 명시한다.

부모 클래스에 해당 함수가 없거나 시그니처가 다르면 컴파일 에러가 발생하므로, 실수를 줄여주는 안전장치가 된다.

### `final`

클래스나 가상 함수가 더 이상 상속되거나 재정의되지 않도록 막는다.

설계 의도와 다르게 확장되는 것을 제한하고 싶을 때 사용할 수 있다.

### `dynamic_cast`

실행 중에 부모 포인터가 실제로 특정 자식 객체를 가리키는지 확인하면서 변환한다.

상속 관계가 복잡할 때 잘못된 메모리 접근을 막는 검문소처럼 사용할 수 있다.

## 배운 점

상속과 다형성은 단순히 객체지향 문법이 아니라, 메모리 구조와 함수 호출 방식까지 연결되어 있다.

특히 `virtual`은 편리한 다형성을 제공하지만, 객체마다 `vptr`이 추가되고 함수 호출 시 간접 참조가 생긴다. 그래서 모든 곳에 무조건 다형성을 적용하기보다, 실제로 실행 시점의 동작 교체가 필요한지 판단해야 한다.

또한 상속과 중첩 클래스는 “코드를 묶는다”는 점에서는 비슷해 보일 수 있지만, 하나는 `Is-A` 관계이고 다른 하나는 범위 제한과 캡슐화에 가깝다. 이 차이를 알고 써야 객체 설계가 덜 흔들릴 것 같다.
