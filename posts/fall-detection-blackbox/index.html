실시간 영상 이벤트를 클립으로 남기는 블랙박스형 로깅 시스템

실시간 영상에서 모션 이벤트를 감지하고, 이벤트 발생 전후 상황을 mp4 클립으로 저장하는 블랙박스형 영상 처리 시스템 개발 기록입니다.

  • C++
  • Python
  • OpenCV
  • Computer Vision
  • Multithreading
  • Logging

1. 왜 이 프로젝트를 만들었는가

낙상이나 이상 행동처럼 특정 이벤트가 발생했을 때, 단순히 “감지했다”는 결과만 남기는 것으로는 부족하다고 생각했습니다. 실제 상황을 확인하려면 이벤트가 발생한 순간뿐 아니라, 그 전후의 영상 흐름이 함께 기록되어야 합니다.

이 프로젝트는 실시간 영상에서 이벤트를 감지하고, 이벤트 발생 전후의 상황을 클립으로 저장하는 블랙박스형 로깅 시스템을 목표로 했습니다. AI 판단 결과와 실제 영상 프레임을 연결해, 이후 상황을 추적할 수 있는 구조를 만드는 데 집중했습니다.

3. 전체 시스템 흐름

카메라 입력, 프레임 처리, 모션 감지, 이벤트 판단, 클립 저장 흐름을 분리해 설계했습니다. 실시간 시스템에서는 한 작업이 지연되면 전체 파이프라인이 멈출 수 있기 때문에, 캡처/처리/저장 흐름을 나누고 상태 로그를 통해 병목을 확인할 수 있도록 했습니다.

Camera Input
→ Frame Capture
→ Motion Detection
→ Event Trigger
→ Buffer / Clip Extract
→ File Save
→ Log Monitoring

4. 핵심 기능

4-1. 실시간 모션 감지

실시간 카메라 입력에서 프레임 단위로 모션 상태를 확인했습니다. 실행 화면에는 카메라 번호, 현재 프레임 번호, Motion YES/NO 상태가 표시되도록 구성했습니다.

주요 기능은 다음과 같습니다.

  • 카메라별 프레임 처리
  • Motion YES / NO 상태 표시
  • 프레임 ID 기반 상태 추적
  • 실시간 로그 출력으로 처리 흐름 확인

4-2. 상태 로그 기반 흐름 검증

실시간 시스템에서는 눈에 보이는 화면뿐 아니라 내부 처리 상태를 확인하는 것이 중요했습니다. 콘솔 로그를 통해 프레임 수, FPS, 모션 비율, 큐 상태 등을 확인하며 처리 흐름을 검증했습니다.

주요 기능은 다음과 같습니다.

  • 카메라별 프레임 수 확인
  • FPS 측정
  • 모션 감지 비율 확인
  • 큐 드롭 발생 여부 확인
  • 시스템 상태 로그 출력

4-3. 이벤트 발생 시 클립 추출

Motion 이벤트가 발생하면 해당 시점을 기준으로 영상 클립을 생성하도록 구성했습니다. 이벤트 결과가 단순 로그로 끝나지 않고, 실제 mp4 파일로 남도록 설계했습니다.

주요 기능은 다음과 같습니다.

  • 이벤트 발생 시 클립 생성
  • 카메라 번호와 시간 기반 파일명 저장
  • mp4 파일로 결과 확인
  • 이벤트 상황 재확인 가능

5. 시스템 설계

실시간 영상 처리 시스템에서는 감지 결과만큼이나 “그 결과가 어느 프레임에서 발생했는지”가 중요합니다. 이벤트 시점과 실제 영상이 어긋나면 이후 확인 과정에서 신뢰도가 떨어질 수 있기 때문입니다.

그래서 프레임 단위로 상태를 기록하고, 이벤트 발생 시 해당 시점의 영상을 클립으로 남기는 구조를 선택했습니다. 또한 처리 상태를 콘솔 로그로 출력해 FPS, 모션 감지율, 큐 드롭 여부를 확인하며 시스템 흐름을 검증했습니다.

감지만 하는 구조
→ 이벤트 발생 사실은 알 수 있지만 전후 상황 확인이 어려움

클립 저장 구조
→ 이벤트 발생 시점의 영상 근거를 남겨 상황 확인 가능

6. 내가 맡은 역할

실시간 영상 처리와 로깅 구조를 담당했습니다. 단순히 화면에 모션 감지 결과를 표시하는 것보다, 이벤트 발생 시점의 프레임과 결과 파일이 연결되도록 로그와 저장 흐름을 설계하는 데 집중했습니다.

7. 개발 중 겪은 문제와 해결 과정

문제 1. 실시간 처리 중 프레임 드롭 발생

카메라 입력과 모션 감지, 저장 흐름이 동시에 동작하면서 프레임 처리가 밀리는 상황이 발생했습니다. 콘솔 로그에서 큐 드롭 발생과 FPS 변화를 확인할 수 있었습니다.

이를 해결하기 위해 프레임 처리 상태를 로그로 확인하며 병목 구간을 추적했습니다. 이후 캡처, 감지, 저장 흐름을 분리하고, 이벤트 상황에서 필요한 데이터만 클립으로 추출하는 방식으로 흐름을 정리했습니다.

결과적으로 프레임 처리 상태를 수치로 확인하면서 시스템의 병목과 드롭 상황을 추적할 수 있었고, 이벤트 발생 시 결과 파일이 생성되는 흐름까지 확인할 수 있었습니다.

문제 2. 이벤트 결과를 어떻게 남길 것인가

Motion YES 상태가 표시되더라도, 결과가 화면과 로그에만 남으면 이후 상황을 다시 확인하기 어렵습니다.

이를 해결하기 위해 이벤트 발생 시 카메라 번호와 시간 정보를 포함한 mp4 클립을 생성하도록 구성했습니다. 결과적으로 이벤트 발생 결과가 실제 파일로 남아, 이후 영상 근거를 통해 상황을 다시 확인할 수 있게 했습니다.

8. 배운 점

이 프로젝트를 통해 실시간 영상 시스템에서는 단순히 모델이 이벤트를 감지하는 것보다, 그 이벤트가 발생한 시점의 데이터를 어떻게 남기고 검증할 것인지가 중요하다는 것을 배웠습니다.

또한 화면으로 보이는 결과뿐 아니라 FPS, 프레임 수, 큐 드롭 여부 같은 내부 상태를 함께 확인해야 시스템의 안정성을 판단할 수 있다는 점을 체감했습니다.

9. 한계와 다음 개선 방향

다음 단계에서는 다음을 보완하고 싶습니다.

  • 단순 모션 감지를 넘어 실제 낙상 분류 모델 적용
  • 이벤트 발생 전후 N초를 안정적으로 보존하는 CircularBuffer 개선
  • 카메라별 비동기 저장 구조 강화
  • 이벤트 로그와 영상 파일을 SQLite에서 연결 관리
  • Streamlit 또는 웹 대시보드로 이벤트 목록 확인 기능 추가

10. 회고

이 프로젝트는 Computer Vision 프로젝트이면서 동시에 실시간 시스템 프로젝트였습니다. AI 모델이 좋은 판단을 내려도, 그 판단의 근거가 영상과 로그로 남지 않으면 실제 서비스에서는 신뢰하기 어렵습니다.

그래서 이 프로젝트에서 가장 중요했던 배움은 “감지”보다 “검증 가능한 기록”이었습니다.
