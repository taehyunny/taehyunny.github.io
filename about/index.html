About

일의 흐름을 정리하고,
작게 구현해 검증합니다.

사용자 문제를 화면 하나로 끝내지 않고 입력값, 저장 구조, AI 응답과 검증 로그까지 이어지는 시스템으로 정리합니다.

일하는 방식

바로 결과물을 만들기보다 이 일이 왜 필요한지, 어떤 문제가 반복되는지부터 확인합니다. 사용자와 운영자의 상황, 현재 확보된 데이터와 기술 제약을 함께 놓고 실행 가능한 범위를 정합니다.

기획 단계에서 만든 기준이 실제 저장 구조와 API 계약, 실패 처리, 테스트 결과로 이어지는지 확인하는 데 관심이 있습니다. 완성형을 한 번에 만들기보다 작은 단위로 구현하고 기록을 남깁니다.

다루는 문제

  • 요청, 검토, 승인과 정산이 이어지는 업무 프로세스
  • 외부 데이터 원본과 서비스 내부 모델을 나누는 데이터 구조
  • AI가 최종 판단자가 아니라 설명과 검토를 보조하는 자동화 흐름
  • 나중에 원인을 다시 확인할 수 있는 로그와 기록 기준
  • API 계약, 스키마, README와 테스트 결과를 통한 협업 기준

요즘 배우고 만드는 것

최근에는 공공데이터 원본을 보존하면서 서비스에서 사용할 수 있는 표준 모델로 바꾸는 과정, 그리고 AI 서버와 메인 서버가 각각 어디까지 책임져야 하는지를 정리하고 있습니다.

동시에 개인 문서와 구현 기록을 사람이 검수할 수 있는 기술 글로 바꾸는 자동화 흐름을 다듬고 있습니다. 자동으로 결과를 내는 것보다, 어떤 근거로 글이 만들어졌고 어디를 다시 확인해야 하는지 드러나는 도구를 만드는 데 관심이 있습니다.

대표 구현 기록

  1. 청년 AI 패스

    공공데이터 원본 보존, Opportunity 표준 모델, 필터와 AI 서버 계약을 설계한 커리어 추천 프로젝트입니다.

  2. 업무 요청·승인·정산 시스템

    엑셀과 구두 보고를 Django 기반 업무 흐름으로 옮기며 상태, 권한과 기록 보존 기준을 정리했습니다.

  3. 주문·결제 데이터 구조

    메뉴가 바뀌어도 과거 주문이 흔들리지 않도록 주문 시점 정보를 스냅샷으로 남기는 구조를 검토했습니다.

  4. 감정 인식 기반 AI 커뮤니케이션

    표정 인식 결과를 사용자 선택과 이전 기록으로 보완해 AI 판단의 한계를 드러내는 흐름을 설계했습니다.

  5. 영상 이벤트 기록 시스템

    감지 결과와 발생 전후 프레임, 클립을 함께 남겨 사람이 다시 확인할 수 있게 구성했습니다.

정태현

AI·데이터 기반 서비스 기획과 업무 자동화를 공부하며, 기획의 언어를 구현과 검증 가능한 기록으로 연결하고 있습니다.

기록의 기준

  • 문제와 완료 조건을 먼저 적습니다.
  • 사실과 가정을 구분합니다.
  • 실패 현상과 원인을 숨기지 않습니다.
  • 실행한 검증과 남은 한계를 함께 남깁니다.
